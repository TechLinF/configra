# 2026-11-04 verification: v1.2.2 security toolchain and UI dependency updates

Scope: branch `release/v1.2.2` on top of v1.2.1 (`f62ad6b`). This records the
review behind the Go 1.26.10 and Vite 8.3.5 updates. It is not release acceptance
for capacity, Kubernetes or production readiness.

## Why

CI on `main` at the v1.2.1 commit started failing only its vulnerability gates
after release:

- `govulncheck@v1.7.0` reports **GO-2026-6809** (`crypto/x509`, fixed in
  go1.26.10) as reachable from both the core and Kubernetes modules.
- `npm audit --audit-level=high` reports high-severity Vite 8.2.x advisories.

## Go 1.26.9 → 1.26.10

- Official source archive `go1.26.10.src.tar.gz`, SHA-256
  `fd63e883ba2f2bfca93c1646b31ebef63e2b1e4d2b317c9789d976a68d81f36f`
  (from `go.dev/dl/?mode=json&include=all`).
- Builder image `golang:1.26.10-bookworm` index digest
  `sha256:23ce71337b726608afb1bc00986e630a05034a87a87ea1fc2cd1ae5cf33387eb`.
  The same `docker buildx imagetools inspect` query on `1.26.9-bookworm`
  reproduces the previously pinned `d9c68c2c…453c`.
- All 40 files in `scripts/go-notices/files.txt` are byte-identical between the
  go1.26.9 and go1.26.10 GOROOTs (`cmp`), so the curated runtime notice bytes are
  unchanged; only version strings and the archive hash in `SOURCE.md` change.
- `go test ./scripts/... ./internal/app/` (including the go-licenses
  package-selection digests) and the `compose-distribution` and `go-notices`
  Node tests pass under go1.26.10.
- `govulncheck@v1.7.0 ./...`: no vulnerabilities in either module.
- `go vet ./...` and `go test ./...` pass for both modules.

## Vite 8.2.2 → 8.3.5

- Only `vite` changed in `package.json`; `rolldown` follows to 1.2.16.
- Rolldown `LICENSE` and `THIRD-PARTY-LICENSE` are byte-identical to the reviewed
  1.2.6 copies. Vite's core MIT text is unchanged; appendix changes are listed in
  `web/scripts/LICENSE-REVIEW.md`.
- `npm audit --audit-level=high`: 0 vulnerabilities. `npm run test:licenses`:
  3/3 pass. Two consecutive production builds are byte-identical.
- Playwright: 79/79 pass (official `mcr.microsoft.com/playwright:v1.62.1-noble`).

## Not verified here

- Full `docker build` could not complete on the development host because its
  x86_64 emulation (Rosetta) failed in an unrelated `npm ci` stage. The `ADD --checksum` step for
  the Debian Snapshot ca-certificates archive did complete and verify.
- Integration, service-image, capacity and Kubernetes gates run in CI/acceptance.
